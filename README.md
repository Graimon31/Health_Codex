# Health Codex

Приложение демонстрирует раздел «Профиль» для медицинских данных пациента на базе Kotlin, Jetpack Compose, Room и DataStore.

## Возможности профиля

- Хранение расширенной медицинской информации: личные данные, диагнозы, аллергии, медикаменты, пороги для сердечных показателей.
- Списки диагноза/аллергий/медикаментов редактируются прямо на экране с подсказками валидации.
- Экспорт профиля в JSON (каталог Documents) и импорт последнего сохранённого файла.
- Генерация и расшаривание ICE-карты (информация для экстренных служб).
- Привязка BLE-устройства (заглушка со списком примерных девайсов).
- Новый раздел «Прогноз»: автоматический расчёт прогноза здоровья и карты самочувствия (что в порядке и что требует внимания) на основе данных профиля.
- Настройки безопасности: биометрическая защита, разрешение HTTP, демо-режим измерений.

## Измерения

- Вкладка «Измерения» объединяет пульс, шаги, калории, давление, вес, SpO₂, сон и дыхание в ленте с группировкой по дням.
- Фильтр периода (сегменты «Сегодня/Неделя/Месяц/Пользовательский») и типовые чипы позволяют быстро сузить выборку; дополнительный нижний лист предлагает фильтр по источнику, устройству и диапазонам значений.
- Каждое измерение отображает источник (устройство/вручную), надёжность, ключевые значения и меню действий: редактирование, удаление, шаринг.
- Экспорт истории в JSON или CSV доступен из AppBar (файлы сохраняются в Documents). Диапазоны фильтров используются при экспорте.
- Диалог добавления/редактирования поддерживает все типы записей: давление с пульсом, сон с периодом, дыхание со статусом. Валидация диапазонов использует те же правила, что и доменная модель.
- Детальный экран отображает показатель в карточке-герое, базовый график (линейный/столбчатый/двойной для давления) и историю дня.

## Прогноз здоровья

- Вкладка «Прогноз» собирает ключевые показатели из профиля и выводит прогноз (заголовок + краткое описание).
- Блок «Что сейчас хорошо» перечисляет сильные стороны пациента (нормальный BMI, отсутствие хронических диагнозов и т. п.).
- Блок «Что требует внимания» подсвечивает риски: повышенное давление, тахикардия, наличие хронических состояний или аллергий.
- Раздел рекомендаций предлагает следующие шаги (консультации, наблюдение, коррекция образа жизни).
- Прогноз строится на базе on-device TFLite модели `app/src/main/assets/ml/health_forecast_model.tflite` с резервным лёгким расчётом при ошибке загрузки; вероятность риска выводится на экране вместе с источником расчёта.
- Если профиль пустой, отображается подсказка с кнопкой перехода к заполнению.

## Биометрия и защита

Включить защиту можно в разделе «Безопасность профиля». При активации флаг сохраняется в DataStore, экран профиля готов к интеграции с `BiometricPrompt` (поведение можно расширить в `ProfileSecurityRoute`).

## Экспорт и импорт

- Экспорт создаёт JSON-файл `HealthProfile_YYYY-MM-DD.json` в системном каталоге Documents (через `MediaStore`).
- Импорт ищет последний сохранённый файл `HealthProfile_*` и подгружает данные в форму редактирования.

## Тесты

`./gradlew test` запускает unit-тесты для валидации профиля, проверки измерений и JSON-сериализации.

## Обновление нейросетевой модели прогноза

1. Подготовьте датасет: нормализуйте числовые признаки (возраст, рост, вес, BMI, давление, пульс) в диапазон [0,1] и выполните one-hot кодирование для пола, хронических заболеваний и аллергий согласно порядку признаков в `NeuralForecastAnalyzer.buildFeatureVector`.
2. Используемый порядок признаков: возраст; пол (one-hot муж./жен./другой); рост; вес; BMI; базовое систолическое/диастолическое давление; пульс в покое; группы хронических состояний ("гиперто", "диабет", "астма", "хобл", cardio, renal, metabolic, onco, прочее); группы аллергий (пыль, пища, лекарства, пыльца, животные, прочее). Числовые признаки min-max, категориальные — one-hot.
3. Обучите MLP: слои 128→64→32 (ReLU), Dropout 0.2 после первых двух слоёв, BatchNorm, выход 3 класса (softmax) или 1 логит (sigmoid) в зависимости от задачи. Оптимизатор Adam (lr=0.001), потери cross-entropy, стратифицированное разбиение 70/15/15, ранняя остановка и ModelCheckpoint по валидационной AUC.
4. Экспортируйте модель в TF Lite: сохраните `model.h5`, затем конвертируйте в `health_forecast_model.tflite` и поместите файл в `app/src/main/assets/ml/`.
5. В Android-приложении убедитесь, что структура признаков при инференсе совпадает с обучением. Для быстрой проверки запустите unit-тесты и открывайте вкладку «Прогноз», чтобы увидеть строку «Вероятность риска: N%».

## Работа с ветками

Актуальный код находится в ветке `work`. Чтобы переключиться на неё в Android Studio:

1. Выполните **Git → Fetch**, чтобы обновить список веток с сервера.
2. В выпадающем меню Git в блоке **Remote** выберите `origin/work` (или `codex/work`, если удалённый репозиторий переименован) и нажмите **Checkout**.
3. В появившемся диалоге подтвердите создание локальной ветки `work` и переключитесь на неё.
4. Проверьте в блоке **Local Branches**, что активна ветка `work` — она содержит все изменения раздела «Профиль».

> Префиксы `origin/` и `codex/` обозначают имя удалённого репозитория. Если видите только локальную ветку `work`, просто выберите её — дополнительные действия не нужны.
